# 照明方向に追従する壁の点列と通常影の精度比較

標準Toonの壁で、照明を回すと通常影の点列が移動する。前回の自作PMXでは、GIによって壁が明るくなるとFXAAを通した後もその点が残りやすかった。所有者の依頼により、今回は検証シーンで通常影の候補を比較し、既定値の判断は結果を見てから行う。[前回の通常影・GI・FXAAの対照](./rc-diffuse-gi-two-bounce-2026-11-22.md#通常影とfxaaで見え方が変わる壁面の点列)

Babylon.js 9.2.0のWebGPU用CSMでは、硬い影はシャドウマップに書いた深度を比較する。半影（PCSS）は遮蔽物までの距離を調べ、受け面でのぼかし幅を変える。アプリの半影設定にはカスケードの分割や安定化の切替も含まれる。形式の精度差を調べる試行は、硬い影の設定をそろえて比較する。[Babylon.jsの影フィルター](https://doc.babylonjs.com/features/featuresDeepDive/lights/shadows/)・[既存のCSM調査と各設定](./csm-seam-parameters-and-official-sources-2026-11-13.md)

## 壁と庇

Windows / Electron / WebGPUで、共通Toon01を持つ自作PMX、RC GI強度0.5・標準・近景0.5倍、FXAAオン、Sky Ambient RCオフ。照明のXを−0.2、Yを−0.65に固定し、Zを変えた。3カスケード、影距離1000、bias 0.0005、normalBias 0.01は各試行で同じ。実際にGPUが確保したテクスチャの形式・寸法・層数と、影を落とすメッシュ6個のIDを照合した。8192角の硬い影で16ビットと32ビットを比較した3方向では、全カスケードの分割と変換行列も一致した。[壁の試験](../test/e2e/rc-moire-shadow-precision.spec.mjs)

下表の暗点は、灰色の正面壁56,961画素のうち、周囲8画素の中央値より5階調以上暗い画素。影オフの対照は3方向とも0だった。容量は3層の色テクスチャと実際の `depth32float` の深度テクスチャの合計を寸法から算出した。プロセス全体の使用量やドライバーの管理領域は含まない。[WebGPUのテクスチャ形式](https://www.w3.org/TR/webgpu/#texture-formats)

| --- | ---: | ---: | ---: | ---: | ---: |
| 現行の硬い影・R16F 8192角 | 6,734 | 6,283 | 5,580 | 1,152 MiB | 5.31 / 6.37 ms |
| 現行＋深度クランプON | 14,021 | 13,405 | 11,889 | 1,152 MiB | 6.27 / 8.25 ms |
| 硬い影・R32F 4096角 | 794 | 0 | 0 | 384 MiB | 5.54 / 6.90 ms |
| 硬い影・R32F 6144角 | 0 | 0 | 0 | 864 MiB | 5.31 / 7.07 ms |
| 硬い影・R32F 8192角 | 0 | 0 | 0 | 1,536 MiB | 5.15 / 6.99 ms |
| 半影（PCSS）・R16F 8192角 | 0 | 0 | 0 | 1,152 MiB | 8.49 / 9.86 ms |

庇下の白壁3,892画素は、通常影オフで約219〜220階調、各方式で約183〜186階調だった。R32F 6144角では正面白壁52,342画素全体で暗点が9〜13画素残った。4096角ではZ=0.51で灰壁に794個、白壁に1,077個が残り、庇の縁に階段が見えた。

候補を選んだ後、照明Zを0.53、0.56、0.59、0.65、0.68、0.70に変えて同じ灰壁を撮った。現行は順に6,844、6,666、6,385、6,084、5,779、5,797個。R32Fの6144角・8192角はどちらも6方向すべて0だった。テクスチャ形式と解像度を戻した後に、検証前の設定と投影メッシュの一致を確認した。

速度はNVIDIA Ampere、描画1152×648、照明Z=0.62の静止画で、描画のCPU開始からGPUキューの完了までを計測した。VSync待ちを外し、各方式10フレームのウォームアップ後に32フレームを測定。中央値が同じでも、別GPUやキャラ再生、高解像度の出力で同じ負荷になるかは未確認。

## 接地影

配布可能な豆腐と皿のPMXを使い、カメラを固定して、通常影オフ、豆腐の投影だけオフ、各方式の影を比較した。高さ3の豆腐を向き（0.3, −1, 0）の光で照らすと、皿上の影の端は豆腐の底辺から0.90ワールド単位先になる。皿の平らな部分を13本の測線で0.01単位（約1.26画素）ごとに測定した。根元の暗さ、影の端で濃さが半分になる位置、90%から10%までの境界幅を調べた。[接地の試験](../test/e2e/rc-moire-shadow-contact.spec.mjs)

全方式で最初の0.01単位の地点に影があり、影の根元は投影を外した対照より44.33階調暗かった。影の端はR32F 4096角で0.91、他の方式で0.90。境界幅はPCSSが0.02、硬い影が0.01単位だった。R32F 6144角はこの測定分解能で現行と同等の接地影を保った。

## 判断

硬い影を保つ候補はR32F 6144角。灰壁の周期的な点列を9方向で解消し、現行より影テクスチャの容量を25%抑えた。柔らかい影が欲しい場合はPCSSも有効で、庇の縁と接地部の境界幅に差が出た。添付画像の街ステージと、カメラ移動中の細い遠景、他のGPUは今回の比較対象外。製品の既定値は現行のままとし、採否は所有者の判断に委ねる。

## 再実行

GPUを使えるローカル環境で次を実行する。各候補での影の形式・設定は検証用Electronプロセスのシーンにだけ適用する。

```powershell
$env:MMD_CSM_SHADOW_PRECISION='1'
npm.cmd run test:e2e -- rc-moire-shadow-precision.spec.mjs rc-moire-shadow-contact.spec.mjs --workers=1
```

実機の比較画像2枚と、壁・追加6方向・接地の生の数値は、検証機の `local-references/csm-wall-shadow-precision-2026-11-23/` に保存した。
