# Luminous RCの受け側プローブ補間をHermiteへ変更

実装日: 2026-10-26。[3D RCの補間・filter調査](./radiance-cascades-3d-filtering-research-2026-10-26.md)に続く、所有者の実装依頼への対応。受け面が遠方のRC fieldを読む際の空間補間を変更した。

## 方式と操作

[receiver shader](../src/render/luminous-radiance-shaders.ts)の8近傍補間で、各軸の小数部`t`を`h(t) = t²(3 − 2t)`へ置き換える。線形補間では格子境界で傾きが切り替わるが、この重みは境界の両側で傾きが0になり、固定fieldの空間補間がC1連続になる。プローブ位置・セル中央・一定の照明値を保ち、近傍値の範囲を超えるovershootを起こさない。

参考にしたのは[Split RC WebGPUの受け側Hermite重み](https://github.com/wroughtinator/split-radiance-cascades-webgpu/blob/34255d334b1fc3880664d2580486bbd111f1be52/public/rc/shaders.js#L1229)。同実装のsurface key、接線上の近傍、irradiance事前積分を取り込んだものではなく、既存の世界座標8近傍へ重みだけを適用した。

RCを有効にすると自動的に使う。新しいUI・保存項目はなく、既存の「RC 柔らかさ」「RC 距離連動」はそのまま使える。所有者が確認した柔らかさ20〜30で比較できる。柔らかさ0は引き続き画面filterを停止するが、受け側の基礎補間は今回のHermiteになる。

変更範囲は以下に限定した。

- cascade同士のmergeは従来の線形補間を維持する。
- 短距離traceと方向別の遮蔽判定は維持し、抜けた方向の遠方fieldだけに適用する。
- 方向数、参照する8近傍、texture load数、compute pass、確保メモリを増やさない。重みの算術は増える。
- receiverのepoch判定も同じ8近傍を参照するため、履歴の有効範囲は変わらない。方向の時間平均は追加していない。
- 発光RGB・通常2D Luminous・材質色の合成には変更を加えない。

## 検証

[GPU検証helper](../test/e2e/helpers/luminous-hermite-probe.mjs)から本番と共通のWGSLを実行した。4³の自作fieldで各軸のprobe値を変え、格子境界前後を0.01セル刻みで比較した。境界の左右の有限差分による傾きの差は、Xで線形1.249993→Hermite0.037253、Yで2.499986→0.074506、Zで0.624996→0.018626。いずれも約97%小さくなった。数学的な境界での微分値そのものではなく、有限幅のGPU計測値である。一定fieldの最大誤差は0で、端・中央・範囲内への収まりも確認した。

実描画は配布可能なtofu材質と、自作の輪状発光・天井・柱を使った。E2E限定でreceiver shaderだけを従来の線形重みへ切り替え、同じfieldと視点で比較した。ユーザー所有モデルは使用していない。

| 補間 | 天井R平均 | 隣接差 / 光量 | 二次差分 / 光量 | R最大 |
| --- | ---: | ---: | ---: | ---: |
| 線形 | 0.490921 | 0.030613 | 0.008328 | 2.208984 |
| Hermite | 0.490915 | 0.032114 | 0.009432 | 2.208984 |

平均の変化は約−0.0013%。PNGでは明るさと柱・輪の形状を保ち、照明の分布がわずかに変わった。ただし、二次差分は約13%増えており、このfixtureで静止した細かい模様を減らす効果は確認していない。格子境界の傾きの連続性と、画像全体の高周波成分の減少は別の指標として扱う。

receiverの切替・カメラ移動前後で、約2 MiBのbase fieldのfingerprintは同一で、cascadeのcacheも維持された。移動後の同じ視点で、履歴を使う結果と全再計算のPNGが一致した。視点を戻した後も、全再計算と履歴利用のPNGが一致した。カメラの位置・注視点の往復は丸めのため元のPNGと10画素・最大1階調だけ異なったため、往復そのものの比較は照明平均と面のsample数で行い、履歴の一致は同じ視点で判定した。背景のRC照明は0。

### 費用の参考値

同一processで線形/Hermiteを2往復し、receiverを全再計算してdispatch・GPU完了を待った。各条件は3回暖機後20回の中央値。線形3.145 / 3.240 ms、Hermite3.640 / 3.395 msだった。この小型fixtureでは約0.15〜0.50 msの増加を観測した。

これはJS・送信・完了待ちを含む壁時計時間で、GPU timestampやアプリ全体のFPSではない。同一process内の参考比較であり、独立process・大型ステージ・再生中の費用は未計測。追加レイ・passがないことを、実行費用が0であるという意味には使わない。

### 確認範囲

- ローカルElectron / WebGPU E2Eは5件成功。HermiteのGPU検証・A/B・移動後の履歴一致、既存の柔らかさ、距離連動の近接光保持・GUI保存復元、曲面再構成、2D発光色基準を確認した。WebGPU validation / page errorは0。
- lintとtypecheck:criticalは成功。通常typecheckは既知547 diagnosticsで、変更前後の位置を除いた内容・件数に増加なし。TS2304 / TS2552は0。
- WGSLの挙動が変更対象のため、実GPU検証を主とし、単体テスト全件と独立した起動smokeは追加実行しない。起動・engine初期化は変更していない。

JSON・比較PNGはignoredな`artifacts/e2e/luminous-hermite/`へ保存した。初回E2Eでは開発依存の追加検出によるVite reloadと、読込通知のPNGへの混入を検出し、テスト側でruntime classの再利用と通知消失待ちに修正した。PNG比較はBufferの一致をbooleanで判定し、失敗時に巨大なbyte差分を生成しないようにした。

## 限界

Hermiteはぼかし半径を広げず、probe中心付近を平らにする一方で、セル内部の変化が線形より急になる場所がある。一定勾配のfieldを厳密に線形再現する方式でもない。画面全体の模様を弱める役割は既存の柔らかさfilterが担う。

固定32方向、接触traceのhit境界、cascade mergeの視差誤差は残る。C1連続という説明は固定fieldの空間補間に関するもので、法線・遮蔽・field更新も含む最終画面全体の連続性を保証しない。所有者の実ステージでの見た目・速度、PNG / WebM exporterでの追加比較は未確認。

同日20:52の所有者の追加画像では、距離連動OFFの固定ぼかしのほうがなじむとの評価を得た（[実機比較](./luminous-radiance-softness-2026-10-26.md#2026-10-26-距離連動の実機比較)）。画像の切替は距離連動で、Hermiteの有無を比較したものではないため、Hermite単独の効果の確認には使わない。
