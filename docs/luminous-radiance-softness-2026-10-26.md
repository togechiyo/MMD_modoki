# Luminous RCの照り返しの柔らかさ

## 観測と調整対象

所有者から、発光面と距離がある天井・柱の周囲に、くっきりした模様が出るという報告があった。添付は通常MMD / Frame Graph / WebGPU、Luminous RCと通常Luminousの併用で、表示は約19〜20 FPS。別の近接画像では髪にも細かな照射の変化が見える。所有者は最近景cascadeの精度が強すぎる可能性を挙げ、具合を調整したいと依頼した。

現行receiverには32方向の固定gatherと短距離の直接traceがあり、角度の離散化や接触光の細部もくっきりした変化の要因になり得る。画像だけから特定cascadeの精度を原因と確定していない。所有者のモデルは探索・読み込みせず、自作の輪状発光・柱・天井でRC照明の調整を検証した。

## 操作

Luminous RC個体に「RC 柔らかさ」を追加。UIは0〜100、保存値は`fixedSettings.radiance.softness`の0〜1。

- 0: 従来の照明を使い、追加のcompute処理を停止する。旧project・旧RC個体も0で復元する。
- 値を上げる: RC照明の細かな変化を面に沿ってなじませる。強度・範囲は別の入力として保つ。
- まず30〜60程度から試し、近接部の必要な細部まで薄くなる場合は下げる。これは使い始めの調整目安であり、所有者の実シーンで確認した推奨値ではない。

個体ごとの固定設定として保存・読込・複製・Undo/Redoに含め、backendの往復でも保持する。enabledと同様のキーを新設する変更ではない。5言語のラベルを追加した。

## 描画処理

[専用shader](../src/render/luminous-radiance-softening.ts)で、receiverの未加工照明から3×3のfilterを5段適用する。sample間隔は1 / 2 / 4 / 8 / 16。前段の結果を次へ渡し、広い範囲を少数の飛び飛びsampleだけで読むことによる複製像を避ける。面を区別した多段filterは[Edge-Avoiding À-Trous Wavelet Transform, HPG 2010](https://diglib.eg.org/handle/10.2312/EGGH.HPG10.067-075)も参照した。本実装は照明の見た目を調整するためのもので、論文全体の再実装ではない。

- receiverが書いたview depth / normalを使い、面からの距離と法線の近さで重みを付ける。共有r16f depthの量子化を許容する。
- 位置復元ではreceiverと同じ全解像度のgeometry画素中心を使う。画面上の距離だけでなく、復元位置の距離も重みに使う。柔らかさ1でbase probeの1セルを目安とする。
- 背景や法線の不連続、離れた平行面を混ぜにくくする。光の明暗自体は保護境界にせず、模様をなじませる対象とする。
- 光だけを処理し、材質色、キャラのtexture、通常2D Luminousには適用しない。
- cascade / trace / 発光RGB専用更新は変更しない。未加工のreceiver履歴とepochを保持し、filter結果をそこへ書き戻さない。柔らかさを変えたときに光場や形状を再計算する必要はない。

filterは長辺640画素以内のreceiver解像度で動く。半精度RGBAのscratchを2枚使い、16:9・640×360では合計約3.5 MiB。0でもスライダー操作時のrebuildを避けるためscratchを準備するが、filterのdispatchは行わない。有効時は毎描画5段のcomputeが増える。追加レイはないがGPU費用が無料という意味ではなく、今回GPU timestampや実シーンの性能差は測っていない。

## 検証

通常光・2D Glowを0にし、配布可能なtofu材質から自作の48分割輪状発光を作った。柱・天井は別の非発光材質。天井内部のreceiver値をGPUから読み戻し、背景や他の面を除いて比較した。shaderが書いた線形照明の指標であり、最終画面のRGBではない。

| 柔らかさUI | 天井R平均 | 隣接差 / 光量 | 二次差分 / 光量 | R最大 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0.490921 | 0.030613 | 0.008328 | 2.208984 |
| 65 | 0.489423 | 0.026750 | 0.003273 | 2.029297 |
| 100 | 0.490150 | 0.026352 | 0.003290 | 2.015625 |

UI 65では平均の変化が約−0.3%、細かな明暗の二次差分が約61%減少。100では隣接差とpeakがさらに低下する。半精度の丸めも含む二次差分のわずかな上下を、単純な単調性の判定に使わない。PNGでも天井の細部がなじみ、柱の形が保持されることを確認した。背景のRC出力は0、0へ戻したPNGは最初の0とファイル内容が一致した。

- 単体203 files / 1,270 tests、lint、typecheck:criticalが成功。通常typecheckの既知547 diagnosticsは位置を除く内容・件数とも増加なし。TS2304 / TS2552は0。
- ローカルElectron / WebGPU E2E 6件が成功。柔らかさの実描画・GUI保存読込・Classic / Frame Graph往復、旧RCの0 fallback、通常Glowと複数RCの独立、2Dとの色基準、曲面の再構成、静止field cache・強度0を確認。WebGPU validation / page errorは0。
- 新設shaderの初回検証でWGSL予約語との衝突を検出し、変数名を修正した。最終6件は修正後のshaderで実行した。
- 起動導線・engine初期化は変更していないため、独立したsmokeは追加実行せず、上記の実際のWebGPU起動で確認した。PNG / WebM exporterでの新しい柔らかさの追加比較は未実施。

JSON・比較PNGはignoredな`artifacts/e2e/luminous-softness/`に保存した。今回のfixtureと元画像の模様を同一原因と断定せず、所有者の実シーンでの調整結果は再確認待ちとする。

## 限界

面光源の物理的な大きさや、光源からの距離に応じた積分を再計算する機能ではない。固定方向の不足そのものや、cascadeの角度・空間解像度は残る。面を区別しても同一面上の遮蔽境界は柔らかくなり得る。r16f depthで区別できない薄い面や、解像度以下の細い形状も完全には保護できない。5段の有限のsample範囲があるため、任意の距離・表示倍率で同じ物理半径を保証しない。
