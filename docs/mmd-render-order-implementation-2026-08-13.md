# MMD 描画順整理 実装メモ 2026-08-13

## 目的

MMD の PMX 材質順を Babylon.js 上でも明示的な固定順として扱い、複数モデルを読み込んだ場合にも半透明材質の順番がカメラ距離で入れ替わらない土台を作る。

MMD 本家寄せを優先する一方、全材質を AlphaBlend にする方式は既存モデルへの副作用が大きいため、既定値は従来の評価方式のまま維持し、実験モードとして分離する。

## 調査結果

確認対象は、現在インストールされている一次ソースである。

- `babylon-mmd 1.2.0`
- `Babylon.js 9.2.0`
- `node_modules/babylon-mmd/esm/Loader/materialBuilderBase.js`
- `node_modules/@babylonjs/core/Rendering/renderingGroup.js`

`babylon-mmd` の `DepthWriteAlphaBlending` は、全材質を AlphaBlend と深度書き込みへ寄せる MMD 互換方式である。`DepthWriteAlphaBlendingWithEvaluation` は不透明と評価した材質を opaque queue に残すため高速だが、全材質を単一の固定順で描く方式ではない。

Babylon.js の標準 transparent sort は、最初に `alphaIndex` の昇順を比較し、同値の場合にカメラ距離の降順へフォールバックする。

### 見つかった問題

`babylon-mmd` は読み込み時に次のような領域を確保していた。

- 最初のモデル: `alphaIndex = 65536` から開始
- モデルごとの増分: `1024`
- モデル内: PMX 材質メッシュ順に `+1`

しかし MMD_modoki は読み込み完了後、各モデルの `alphaIndex` を毎回 `0, 1, 2 ...` に振り直していた。そのため複数モデルの同じ材質番号が同値になり、透明材質の最終順序がカメラ距離依存へ戻っていた。

## 実装

### 描画番号

アプリ側で描画番号の割り当てを一元化した。

```text
alphaIndex = 65536 + modelRenderOrder * 4096 + materialOrder
```

- `modelRenderOrder`: モデル描画順ダイアログで変更する順位
- `materialOrder`: PMX 読み込みで得た材質メッシュ順
- シーンの `sceneModels` 配列は並べ替えない

シーン配列を維持する理由は、外部親、カメラ外部親、アクセサリ親などがモデル index を参照しており、描画順変更で編集対象まで入れ替わる回帰を避けるためである。

### UI

`表示 > モデル描画順...` を追加した。

- 上下ボタンでモデルの描画順位を変更
- 上から順に描画
- 各 PMX 内部の材質順は維持
- 描画方式をモデル未読込時のみ選択可能

描画方式は次の二つ。

- `評価方式（既定）`: 従来の `DepthWriteAlphaBlendingWithEvaluation`
- `MMD固定順（実験）`: `DepthWriteAlphaBlending`

MMD 固定順では、読み込み後の互換補正が opaque や depth-write off に戻さないよう、最終段で全 PMX 材質へ AlphaBlend と深度書き込みを再適用する。

### 同一平面補正

ステージ PMX 内でほぼ同じ位置に置かれた床・模様・影受け面の Z-fighting を抑えるため、モデル描画順パネルへ全モデル共通の `同一平面補正` を追加した。既定値は `OFF`、強度は `1`（弱）から `4`（強）までとする。

補正は全 PMX 材質へ一律適用せず、各モデル内部で次を満たす材質メッシュだけを候補にする。

- PMX 実頂点から求めた AABB が軸に沿った薄い平面である
- 重なる候補の一方が幅 5 MMD 単位以上である
- 薄い軸方向の距離が許容値内で、平面上の投影領域が 5% 以上重なる
- PMX 材質順が後の候補へ `zOffsetUnits` のみを段階的に付ける

`zOffset`（傾斜依存）は使わず、強度 `1 / 2 / 3 / 4` を一段あたり `1 / 2 / 4 / 8 units` に対応させ、定数バイアスを最大 64 units に制限する。キャラクターの顔・まつ毛・衣装など小さい重なりへ全体補正が波及した過去の問題を避けるため、大型薄型面に限定した暫定対処である。形状そのものや物理位置は移動しない。

`St.05 Cyber Stage Ver.1.2A.pmx` の実データでは、材質 `05` と `06` がそれぞれ 60 三角形、同一座標・同一境界で完全に重複していた。初版の最大 16 units では後半材質が同じ上限値へ飽和して再競合したため、上限を 64 units へ広げ、最大強度でも材質ごとの値を分離できるようにした。

また Babylon ランタイムの `BoundingInfo` にはこのモデルで各軸 10 units の安全余白が入り、厚さ 0 の床材質が厚さ 20 と判定されて補正対象が 0 件になっていた。判定用境界は `getVerticesData("position")` の実頂点から独自計算する。再現モデルを読み込む E2E 調査では、最大強度で `01～07` が `0, -8, -16, -24, -32, -40, -48` units に分離されることを確認した。

### 保存

プロジェクト v1 の後方互換な optional field として保存する。

- `scene.renderOrderMode`
- `scene.coplanarMaterialDepthBiasStrength`
- `scene.models[].renderOrder`

旧プロジェクトでは `evaluated` とモデル配列順へフォールバックする。

## 制約

- 描画方式はモデル読込後に即時変更しない。既存材質を評価方式へ正確に戻すには、ローダーの判定結果を再構築する必要があるためである。
- `評価方式` では opaque queue と transparent queue が分かれるため、モデル描画順は主に透明材質間へ作用する。
- `MMD固定順` は MMD 寄せだが、全材質が transparent queue に入るため性能と汎用 PostFX / PBR 互換性に影響しうる。
- エッジ、影、Mirror、FrameGraph 各パスがすべて MMD 本家と同一順になる保証はまだない。
- 同一平面補正の初期判定は軸に沿った AABB を使うため、傾いた床や複雑な一体メッシュは検出しない場合がある。
- 半透明材質同士の通常の前後関係は描画順で扱い、同一平面補正は Z-fighting 用に限定する。
