# 読み込みモデル個体 ID 実装メモ（2026-08-14）

## 目的

同じ PMX / PMD ファイルを複数回読み込んだ場合でも、各モデルを別個体として扱えるようにする。

従来はプロジェクト保存・復元の一部でモデルパスを識別子として使っていた。このため、バックダンサーのように同一モデルを複数体配置すると、次の状態が先頭または末尾の個体へ混線した。

- 個体ごとの埋め込みモーション
- アクティブモデル
- モデル外部親とそのキーフレーム
- カメラ外部親とそのキーフレーム
- アクセサリ親
- DoF の注視モデル

## ID の責務

- `ModelInfo.instanceId` を読み込み済みモデル個体の主識別子とする。
- ファイルパスはアセットの再読込先であり、個体識別子にはしない。
- 配列 index は実行中の UI 選択用であり、削除や読込順で変わるため永続識別子にはしない。
- 新規読み込みでは `crypto.randomUUID()` を優先して ID を発行する。
- UUID が利用できない環境では時刻と乱数からプロジェクト安全な文字列を発行する。
- プロジェクト復元では保存済み ID を再利用する。
- 不正または読み込み中に重複する ID は採用せず、新しい ID を発行して warning ログへ残す。

ID は空白を含まない最大 128 文字とし、`A-Z a-z 0-9 . _ : -` を使用できる。ID はユーザー向け名称ではなく、保存・参照のための不透明な値として扱う。

## project JSON

プロジェクト version は `1` のままとし、次の optional field を追加した。既存の path field は旧ファイルの読み込みと外部調査のしやすさのため併記する。

- `scene.models[].instanceId`
- `scene.activeModelInstanceId`
- `keyframes.modelAnimations[].modelInstanceId`
- モデル外部親の child / parent instance ID
- カメラ外部親の model instance ID
- アクセサリ親の model instance ID
- `effects.dofTargetModelInstanceId`

新形式の参照解決では ID を優先する。ID が書かれているのに該当個体が存在しない場合、同じパスの別個体へ暗黙に付け替えない。削除済み個体への参照が、同一モデルの別個体へ移る事故を防ぐためである。

## 旧プロジェクトの移行

instance ID がない version 1 ファイルも読み込める。

- 各モデルには読み込み時に新しい ID を発行する。
- `keyframes.modelAnimations` は同一パスごとのキューを作り、モデルの出現順に割り当てる。従来の `Map<path, animation>` のように末尾のモーションで上書きしない。
- path しかない単一参照は従来どおり最初に一致した個体へ解決する。
- 一度新形式で保存すれば、その後は ID で安定して復元できる。

旧形式の path-only な外部親、アクティブモデル、DoF 対象などは、同一パスが複数ある時点で元の個体情報を保持していない。この曖昧性を完全に復元することはできない。

## UI と削除

- モデル一覧は従来どおり読み込み順番号を表示し、同名モデルを選択できる。
- DoF のモデル候補にも `読み込み順番号: モデル名` を表示する。
- モデル削除時は、削除した instance ID を参照するモデル外部親、カメラ外部親キーフレーム、DoF 対象だけを解除する。
- 同じパスを持つ別個体の参照は維持する。

## テスト

追加した主な回帰確認:

- ID の正規化、生成、既存 ID との非衝突
- 同一パスのモデル 2 体へ別々の埋め込みモーションを保存し、ID ごとに復元
- 同一パスの 2 体目をアクティブモデルとして復元
- serializer がモデル、アクティブモデル、モーション、外部親へ ID を保存
- 既存の path-only project importer / serializer テストを維持

確認コマンド:

```powershell
npm.cmd run test:unit
npm.cmd run lint
npm.cmd run typecheck:critical
```

## 今後の確認

- 実 PMX を同一ファイルから 4 体読み込み、別モーション・配置・外部親を設定した project round-trip の E2E / 手動確認
- 不正・重複 ID を含む手編集 project の warning 表示方針
- 将来 project schema のメジャー更新を行う場合、path fallback を残す期間の再評価

## 実機確認（2026-08-14）

ユーザー環境で `Tda式初音ミクV4X_Ver1.00` を同一ファイルから 3 体読み込み、WebGPU / WGSL / Bullet HPR Buffered でモーション再生できることを確認した。表示上、同一モデル複数読込に起因する個体の混線や再生異常は見られなかった。

この確認は同時読込・選択・再生の基本確認である。別モーション、外部親、project 保存後の再読込までを組み合わせた round-trip 確認は引き続き上記の確認項目として残す。
