# 物理ジョイント沈下・伸長調査 2026-08-13

## 結論

`可変追従ボーン_Ver2.pmx`と最小fixtureで見える定常的なY沈下は、外部親やsolverの位置誤差ではない。
Y軸が自由な線形バネへ重力荷重が掛かったときの静的変位である。

一方、他モデルで見える一時的な「伸び」には別の過渡応答が含まれる。完全ロック軸へ追従元を瞬間移動した試験では、
1/60秒stepで大きなオーバーシュートを再現した。1/120秒stepでは最大誤差が縮小したため、固定stepと拘束収束性が有力な要因である。

## 定常沈下の測定

最小fixtureの条件:

- 動的剛体の質量: `1`
- 重力: `98`
- Y軸バネ: `388`
- Y軸移動範囲: `-1000..1000`（自由軸）

線形バネの静的釣り合いは次になる。

```text
変位 = 質量 × 重力 / バネ定数
     = 1 × 98 / 388
     ≈ 0.25258
```

Electron上の約1秒後の実測値はY=`-0.25244`だった。重力を`9.8`へ変更するとY=`-0.025245`となり、
重力と沈下量が10分の1で比例した。理論値と実測値が一致するため、これは正常なバネ伸長である。

この種類のカメラリグで上下へ沈ませたくない場合は、PMX側でYをロックする、Yバネを十分強くする、
またはカメラへ渡す出力からY成分を分離する設計が候補になる。ただしMMD本体で同じPMXが沈まないなら、
PMXの意図は減衰 `1.0` 剛体に対するMMD本体の実効重力・減衰処理を前提にしている可能性が高い。

MMD本体は非公開実装であるため、Bulletの版だけが原因とは断定できない。静的な釣り合い量はstep幅では変わらず、
現行経路で重力を10分の1にすると沈下も10分の1になった。したがって本件のMMD差はsolver精度より、
古いBulletを含むMMD本体の統合方法で減衰 `1.0` 剛体へ入る実効重力が小さい、または姿勢同期で相殺される、
という互換差が有力である。

アプリ側では全剛体のYを一律補正せず、既存の `物理互換補正` のうち、FollowBone剛体と直接接続され、
Y移動制限が実質自由、Y線形バネが有効、かつ減衰 `1.0` 相当のdynamic剛体だけを対象にする。
`重力補正量 = 1.00` を gravity scale `0.0` へ拡張し、このカメラリグでは重力を相殺できるようにした。
既定値は引き続きOFFとし、髪・衣装など本来重力で垂れるモデルへの誤適用を避ける。

複数キャラとの同時利用で全減衰 `1.0` 剛体を対象にするとキャラ物理への影響が大きいことを確認したため、
モデル単位の個別設定ではなくjoint構造による判定へ変更した。スライダー既定値も減衰 `0.00`、重力 `1.00`、
質量 `0.00` とし、互換補正ON直後は特殊な自由軸バネ重力補正だけが動くようにした。

この対応は原因の完全再現ではなく暫定対処である。MMD本体が沈下しない正確な内部条件は非公開であり、
Bullet 2.75、減衰 `1.0` の扱い、constraint評価順のどれが支配的かは確定していない。
そのため現行実装では、再現モデルで確認できた定常沈下だけを反重力で相殺し、PMX構造条件によって影響範囲を限定する。
キャラモデルを含む比較検証で誤検出が見つかった場合は、閾値や構造条件を優先して見直し、モデル名による例外追加は行わない。

最小fixtureのE2Eでは、補正OFFで出力Yが `-0.15` 未満まで沈むこと、補正ON・重力補正 `1.00` で
`|Y| < 0.05` へ戻ることを確認した。その状態でも水平遅延とカメラ外部親の追従は維持された。
動的外部親後の追加剛体同期では重力相殺力を再注入しないため、二重補正による上向きの沈み込みも発生しない。

## 過渡的な拘束伸長の測定

比較用にY軸を`0..0`へ完全ロックし、追従元をY=`0`から`10`へ瞬間移動した。

1/60秒stepでの出力Y:

```text
2.74 -> 14.24 -> 12.32 -> 11.22 -> 10.63 -> ... -> 10.01
```

追従剛体の速度同期補正を無効にしても、最大値は約`14.42`でほぼ変わらなかった。
したがって、この補正は主因ではない。

fixed timestepを1/120秒にした比較:

```text
10.87 -> 12.35 -> 10.66 -> 10.18 -> 10.05 -> ... -> 10.00
```

1/120秒では最大オーバーシュートが約`4.24`から約`2.35`へ減った。
現行babylon-mmdの`IMmdPhysicsCreationOptions`にも、`disableOffsetForConstraintFrame`で拘束が壊れる場合は
fixed timestepを1/120秒以下へするよう注意書きがある。

## 現時点の判断

- 定常沈下: PMXの自由軸バネと重力による仕様どおりの変位。
- 瞬間的な伸び: 大きな追従元移動を1/60秒で解く際の拘束過渡応答。
- 追従剛体速度同期: 今回の伸びの主因ではない。
- CFM / ERP: 現行値はCFM=`0`、ERP/StopERP=`0.475`であり、柔らかいCFMによる定常伸びではない。
- solver iteration: 現行Bullet wasm bindingから変更できず、実行値も未確認。
- MMD本体との差: Bullet版だけとは断定できないが、減衰 `1.0` 剛体の実効重力・姿勢同期の互換差が有力。
- アプリ側対策: `物理互換補正` の最大重力補正で対象剛体の重力を相殺する。既定OFFは維持する。

## 次の比較候補

1. `disableOffsetForConstraintFrame: false`を1/60秒で比較する。
2. 実在の長髪・スカートモデルを同一モーションで1/60秒と1/120秒比較する。
3. 1/120秒を設定または互換モードとして公開する場合、CPU負荷とBuffered評価の遅延を測定する。
4. solver iterationを取得・設定できるAPIをbabylon-mmd / Bullet wasm bindingへ追加可能か調査する。

1/120秒を即座に既定値へ変更するのは避ける。物理負荷が概ね増え、既存モデルの揺れ方も変わるため、
複数モデルでの比較と性能測定を先に行う。
