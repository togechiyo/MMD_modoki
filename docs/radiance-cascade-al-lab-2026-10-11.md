# AutoLuminous 発光面による 3D Radiance Cascades 検証画面

実装・確認日: 2026-10-11

追記: 通常シーンへの接続は [既存 Luminous 材質への 3D RC 接続](./luminous-radiance-integration-2026-10-11.md) で実装した。以下の説明は、通常シーンと独立した検証画面自身の仕様を扱う。

AutoLuminous の発光部分で周囲を照らす構想に向け、独立した WebGPU 検証画面を追加した。ツール →「AL照明 3D RC実験...」から開き、自作の発光面・床・壁・球・遮蔽物で色移りを比較する。[調査メモ](./radiance-cascades-3d-research-2026-10-11.md) の最初の試作段階に相当する。

現在の AL 材質評価、読み込んだ PMX / ステージ、通常の PostFX には接続していない。光源は AL の emission 接続を模した単色の面であり、既存 AutoLuminous を利用する機能が完成したとは扱わない。Split RC の hash map や BVH を再現したものでもない。外部実装のコードや asset は取り込まず、WGSL と解析的な形状を自作した。

## 操作と保存

- 発光面、RC による周囲の照明、Glow、遮蔽物を個別に切り替える。
- 発光色、照明の強さ、遮蔽物の位置を調整する。
- 視点を「発光面を画面外にする」へ切り替え、Glow を OFF にして床や球への照明だけを見る。
- 設定を専用 JSON として保存・再読込する。形式は `mmd-modoki-radiance-lab`、version は `1`。通常の project 保存とは別で、画面を閉じて開き直す間は値を保持する。
- GPU timestamp query が利用可能なら照明計算と表示の時間を示す。非対応の場合は計測不可と表示する。

同梱コードだけで実行し、外部ネットワークには接続しない。MCP のメニュー一覧には説明用の項目を追加したが、実験設定の MCP 操作は未対応である。

## 計算方式

世界座標の `9 × 6 × 9` の範囲に、密な 3D 格子を置く。各プローブは球面を等面積の方向に分け、距離区間内で最初に当たる面の emission と透過率を記録する。形状との衝突は SDF の sphere tracing で判定する。

| 段 | 格子 | 方向数 | 距離区間 | RGBA16F atlas |
| --- | --- | --- | --- | --- |
| 0 | `16³` | 32 | `0..0.5` | `128 × 1024` |
| 1 | `8³` | 128 | `0.5..2.5` | `128 × 512` |
| 2 | `4³` | 512 | `2.5..10.5` | `128 × 256` |
| 3 | `2³` | 2048 | `10.5..42.5` | `128 × 128` |

遠い段から順に計算し、親格子を三線形補間して、4つの子方向に対応する方向の結果を平均する。合成は `L = Lnear + Tnear × Lfar`、`T = Tnear × Tfar` で行う。atlas 合計は 1,966,080 bytes（1.875 MiB）。HDR の表示用 texture、uniform、timestamp buffer などはこの値に含まない。

受け手では段 0 の32方向を cosine 加重で積分し、Lambert の拡散照明として表示する。表面から `0..0.5` の近接遮蔽は追加で直接追跡し、格子補間による接触部分の光漏れを抑える。発光色は sRGB から線形へ変換し、照明計算の後に発光面だけの Glow を合成してから一度 tone map する。

表示解像度は `560 × 315`。設定変更時だけ描画し、操作中に届いた新しい値は直前の GPU 処理後にまとめて反映する。発光色・強さ・ON/OFF、遮蔽物・位置が変われば格子を再計算する。視点、Glow、RC の表示 ON/OFF は格子を再計算しない。履歴の蓄積はない。

専用の WebGPU device / canvas を使い、通常シーンの Classic / Frame Graph から独立させた。閉じると texture・buffer・query・device を破棄し、初期化中に閉じた場合も、完了後にその instance を破棄する。

## 実機確認

ローカルの GPU を使う Electron で [E2E](../test/e2e/radiance-cascade-lab.spec.mjs) を実行し、両 backend で次を確認した。ユーザー所有のモデルは利用していない。

- 画面外の発光面と Glow OFF の条件でも床・壁・球へ発光色が届く。RC OFF、発光 OFF で色移りが消える。
- 赤から青へ発光色を変えると、受け手の照明も変わる。
- Glow の ON/OFF で表示が変わり、視点・Glow の変更では格子の更新世代が変わらない。
- 光源から見て遮蔽物の後ろにあり、カメラからは見える床上の点 `(0, 0, 0.5)` で比較した。9 × 9 pixels の青チャンネル平均は遮蔽あり `45.11`、なし `57.52` で、遮蔽物を外すと明るくなった。値は tone map 後の8bit画像であり、物理量ではない。
- 初期値、保存、リセット、再読込、再表示、無関係な設定 JSON の拒否を GUI から確認した。
- 開閉後に通常シーンの project effects が変わらず、通常 device の GPU validation count と page error がともに0だった。実験 device のエラーは画面の status で検出する。

取得した screenshot も目視し、色移りと遮蔽物付近の暗部を確認した。ただし参照 path tracer との比較や、薄壁での漏れの定量評価は行っていない。

初期状態の照明計算は Classic `0.20 ms`、Frame Graph `0.26 ms`、RC ON の表示は確認した各状態で約 `1.4..1.8 ms` だった。専用 device の timestamp query による少数サンプルで、CPU 時間・初期 shader compile・通常シーン・スキニング・BVH 更新を含まない。MMD モデルへ適用した性能の見積もりには使わない。

検証結果:

- `npm.cmd run test:e2e -- radiance-cascade-lab.spec.mjs`: 2件成功。
- `npm.cmd run test:unit`: 175 files / 1054 tests 成功。
- `npm.cmd run lint`: 成功。
- `npm.cmd run typecheck`: 既存の型エラーで終了。今回追加したファイルと変更した menu controller / catalog にエラーなし。
- `npm.cmd run typecheck:critical`: 成功。`TS2304` / `TS2552` なし。
- `npm.cmd run smoke:launch`: WebGPU 初期化・安定性確認成功。

## 残る接続と限界

発光から拡散面へ届く一回の輸送だけを扱い、受け手の色を新たな光源へ戻す多重反射、鏡面、透過、alpha test は扱わない。格子と方向数の有限解像度により、光漏れ、陰影の粗さ、角度ごとの誤差は残り得る。カメラは2種類の固定視点で、PNG / WebM の通常出力には接続していない。

次に通常シーンへ接続する場合は、既存 AL の対象判定・モーフ評価から線形 emission を共有する境界と、世界座標の追跡用形状を先に用意する。静的ステージ / 剛体から検証し、PMX のスキニング・モーフ、MMD 材質への照明合成、seek・出力へ進む。既存 SSGI / RSM GI / 環境光との寄与の重複も、その段階の確認対象とする。本試作だけで通常シーンへの採用は確定しない。
