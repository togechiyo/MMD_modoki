# GI RCの近距離2バウンス

方向光に照らされた色面から床や壁に届いた光を、もう一度拡散反射させる。GI RCを有効にすると、原点中心の一辺128の領域で2バウンスが働く。外側3領域は1バウンスを使う。手動範囲を保存しているプロジェクトではその範囲が2バウンスの対象になる。

## 光の計算

1回目の反射を6方向の線形照度として保存する。最内領域の16³個のプローブからそれぞれ32方向にレイを飛ばし、最初に当たった面でこの照度を読む。受光面の法線と遮蔽を考慮し、面の拡散反射率を掛けて2回目の寄与を得る。領域内のヒットだけを採用し、2回の照度を合算した結果を既存の材質から参照する。表示用の強調倍率は最後に一度だけ掛ける。

光場の更新時に、2回目の輸送と照度の合算を1回ずつGPUで実行する。三角形の探索構造と遮蔽判定用の近傍情報を共有する。中間テクスチャの追加容量は約1.19 MiB。静止中は合算済みの結果を再利用する。タスクの実行順とテクスチャ依存関係は Babylon.js 9.2.0 の実装と照合した。[Frame Graph のタスク](https://doc.babylonjs.com/features/featuresDeepDive/frameGraph/frameGraphClassFramework/frameGraphWritingTasks/)

## 比較条件

色移りの比較では、自作の赤い床と灰色の受け面を同じ高さに置き、その上に反射板を配置した。赤い床と受け面の間には黒い仕切りを置いた。反射板を白から黒へ替えた場合と、赤い床自体を黒に替えた場合を比較する。PNG中央の同じ5,400画素で、GIのONとOFFの差から赤成分の増加量と緑・青の平均増加量との差を求める。[描画テスト](../test/e2e/rc-diffuse-gi-two-bounce.spec.mjs)

| 測定面と条件 | 1バウンスの赤み（8ビット階調） | 2バウンスの赤み（8ビット階調） |
| --- | ---: | ---: |
| 白い反射板の下面 | 46.10 | 46.10 |
| 灰色の床（赤い床と白い反射板） | 0.00 | 11.34 |
| 灰色の床（赤い床と黒い反射板） | 0.00 | 0.00 |
| 灰色の床（黒い床と白い反射板） | 0.00 | 0.50 |

灰色の床をアップにした構図では、赤い床も反射板も画面外にある。2バウンス版では、赤い床と白い反射板がそろったときにだけ、灰色の床に明確な赤みが届いた。黒い床と白い反射板の組み合わせではRGBの増分はそれぞれ2・1・2階調で、ほぼ無彩色だった。原点4領域・手動1領域の両方で同じ結果を確認した。

## GPU更新時間

WindowsのWebGPU実機（NVIDIA Ampere）、1280×720、既定の原点4領域で、同じPMXの遮光板ボーンを動かした。旧版（`4740b84`）と2バウンス版で、12フレームのウォームアップ後に40フレームのGI compute時間をGPUタイムスタンプで測った。高密度版は同じ3箱を細分化し、GIの三角形探索に20,736枚すべてが入ることを実行時に照合した。

| シーン | 1バウンスの中央値 | 2バウンスの中央値 | 増加 |
| --- | ---: | ---: | ---: |
| 36三角形・ボーン移動 | 0.394 ms | 0.428 ms | 0.034 ms（8.6%） |
| 20,736三角形・ボーン移動 | 0.971 ms | 1.062 ms | 0.091 ms（9.4%） |
| 36三角形・静止 | 0 ms | 0 ms | 0 ms |

ボーン移動では1フレームのGI dispatch数が24回から26回に増えた。静止中はどちらも0回。表は上記シーンのGI更新分に限り、FPS換算やモデル全体の変形・描画時間の推計には使わない。

ローカルのGPU環境で次のPowerShellコマンドから再確認できる。1つ目は画面外からの色移り、2つ目は高密度・ボーン移動の計測。環境変数 `MMD_RC_GI_PERF_DENSE` を省くと36三角形を使う。

```powershell
npm.cmd run test:e2e -- rc-diffuse-gi-two-bounce.spec.mjs
$env:MMD_RC_GI_PERF_VOLUME='origin'
$env:MMD_RC_GI_PERF_DENSE='1'
npm.cmd run test:e2e -- rc-diffuse-gi-performance.spec.mjs -g 1280x720-moving-on
```
