# 数値中心のエフェクト5種をタイムラインへ移行

更新日: 2026-09-14

[共通基盤](./effect-timeline-common-foundation-design-2026-09-14.md)と[ブルーム](./bloom-timeline-key-2026-09-14.md)に続き、所有者の「移行できそうなものの対応」依頼を受けて数値中心の5種類を追加した。キー対応はガンマ・グレイン・ブルームを合わせて8種類。

## 対応項目

カメラモードに1エフェクト1行。各キーにON / OFFと表の数値をまとめる。ON / OFFはstep、数値は実値の線形補間。

| 効果 | 保存する値 | 実値範囲 | タイムラインのスライダー |
| --- | --- | --- | --- |
| ビネット | weight | 0〜4 | 0〜100% |
| シャープ | edge | 0〜4 | 0〜100% |
| 色収差 | amount | 0〜200 | 0〜100% |
| エッジブラー | strength | 0〜3 | 0〜300%（既存実値×100） |
| レンズ歪み | influence | 0〜1 | 0〜100% |

エッジブラーのruntimeは従来から0〜3を許可している。右の共通スライダーは0〜100の表示範囲を実値0〜3へ対応させ、旧パネルも300%まで表示する。保存値の単位は変えない。

レンズ歪みは既存の画角連動を維持する。30度で中立、広角で樽型、望遠で糸巻き型となる既存計算に、キー評価した影響度を掛ける。歪みそのものの符号を新しいスライダーで直接登録する仕様ではない。

## 値と描画の分離

- 共通store、effect payload、新形式保存、コピー・削除・Undo / Redoは既存基盤を使用する。
- OFF・スタックからの削除は描画用の強度だけをゼロにする。キーの数値・base・未登録previewを破壊しない。
- projectの静的設定には専用の取得口から元の設定を保存し、シークした途中値を混ぜない。停止中previewは従来どおり別途保存し、出力では使わない。
- スライダー定義へ既存右パネルのフィールド名を追加し、readout更新の効果別switchを廃止した。選択値と既存パネルを同期し、再生中は入力をロックする。

Classicのシャープ・色収差とビネットのimage processingは、キーを持つ間に必要な処理を準備する。値の評価ではUI setterを呼ばず、確保済み処理の強度だけを更新する。エッジブラーもゼロで破棄しない。FrameGraph中にClassicのエッジブラーを生成しないようbackend条件を明示した。

FrameGraphは既存の記録済みdisabled passを利用する。ビネット・エッジブラーは同じcompositeを共有するが、キーと強度は独立して扱う。レンズ歪みは描画直前のカメラ画角から求め、PNG/WebMでも同じ評価経路を使う。

## 調査で見つかったUI初期化の問題

既存のLensEffectControllerはパネル接続時に表示用スライダー値を設定へ書き戻していた。エッジブラーの150%キーを保持したままbackendを切り替えると、旧パネルの上限100%に丸めたpreviewが作られた。

接続時は表示更新だけにし、入力イベントでのみ編集するよう変更した。影響度にも同じ精度保持を適用。関連する旧ビネットパネルで強度変更がON/OFFを暗黙に上書きしていた処理も、キー所有中はenabledを保つ。

## 外部実装の確認

依存はBabylon.js 9.2.0。インストール済み一次ソースのThinSharpenPostProcess.bind、ThinChromaticAberrationPostProcess.bindを確認し、edgeAmount / aberrationAmountがuniformへ反映されることを確認した。FrameGraphSharpenTask.recordが入力解像度を設定する経路も確認した。画角連動の計算は既存式をpure helperへ移し、広角・望遠・中立・影響度ゼロをunit testで確認した。

- lint: PASS。
- typecheck:critical: PASS。通常型検査は既存544件、TS2304 / TS2552は0。前回ブルーム完了時から診断の追加なし。
- ローカルGPUで5種類×Classic / FrameGraphのGUI登録、補間、Undo / Redo、保存読込、previewと静的設定の分離、PNG/WebMを確認。初回10ケース中6件通過、シャープ・エッジブラーの修正後の4ケースも通過。

出力比較はfixtureのtofu.pmxのみ使用。シャープでは強い輪郭処理が細かな画素差も増幅し、動画圧縮も高周波を変えるため、ONのPNGとの画素一致だけでは判定しない。エッジブラーも動画圧縮のぼかしと競合する。両者は動画内のON/OFF差がOFF/強度ゼロ差の2倍を超えることを確認する。PNGではOFFと強度ゼロが一致すること、他の3種類では動画各状態が対応するPNGへ近いことを確認する。WebMをデコードした画像もartifactへ保存して目視確認した。
