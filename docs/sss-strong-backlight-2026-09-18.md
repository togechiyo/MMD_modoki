# SSSの強い逆光と顔全面の白飛び

## 条件と目的

所有者が、薄い耳や指先の透過と、輪郭の強い逆光ハイライトを残しつつ、顔全体が発光して見えない絵作りを希望した。照明RGB255・影欄の照度200で、明示的に使用許可されたローカルリファレンスのAliciaを比較した。材質はbody / hand / faceへ適用し、それ以外は各モードの標準材質を維持する。

標準照明RGB128・照度100、最大照明RGB255・照度200、斜め逆光(0.56, -0.74, -0.65)、真後ろ(0, 0, -1)、順光(0.3, -0.3, 0.9)を通常MMD / PBRで撮影する。PostFXスタックは空の初期状態で、Bloomの増幅を含めない切り分けとした。所有者の元画像と全設定が一致する再現ではない。

## 確認できたこと

- 厚みの入口描画はSSS材質だけでなく、同じskeletonを持つモデルの髪・衣服などを含む。Aliciaでもhairなどが実際の描画リストに入っていた。材質が分離されているだけで顔の厚みがゼロになる実装ではない。
- 入口が見つからない画素は`entryWeight`によるvalid判定で透過を0にする。片面・開いた形状を、入口なしだから厚み0として最大透過にする処理ではない。ただし単一の入口depthは閉じた体積の保証ではなく、耳・指先の正確な厚みを全モデルで保証するものではない。
- 入口描画だけを一時停止し、透過光を0にしても顔全面の白さがほぼ残った。PBRの口周辺固定ROIではRGB平均254.78→254.61/255で、今回の白飛びの主因は透過係数ではなかった。
- Skinの陰側の固定色は照明に比例して持ち上がる。通常MMDでは光RGBが1まで、PBRでは2まで届き、照度2を合わせるとそれぞれ最大2倍・4倍になる。既存の透過半減だけでは、この陰側の底上げを抑えられない。

## 局所修正

`owned-sss-shaders.ts`のSkinの陰側の色だけに、`1 / max(1, max(lightRGB × intensity))`を適用する。光のRGB比を維持し、通常程度の光に対する応答は保ちつつ、強い逆光で陰側の固定色まで増幅され続けることを抑える。

通常MMDはgamma側の陰色に適用する。PBRは既存のgamma側surface helperに対応するgamma換算係数を掛け、呼び出し側でlinearへ戻す。直接光を受ける端点、透過係数0.375、厚み判定、拡散半径、Wax、シーンの影設定、IBL、反射は変更しない。中間の受光角度では陰側と明部の補間が変わるため、最大照明の順光画像まで全画素一致する変更ではない。

## PBRで残る環境光との加算

陰側の増幅を抑えた後も、初期の雪原HDRIの環境光を加えるとPBRの顔には白さが残る。直接反射だけを無効にしてもほぼ変わらず、環境光だけを無効にすると陰影が戻った。SSSの直接拡散だけを取り出した比較では、標準・最大照明の両方で陰側が残る。

逆光の見本用に、SSS対象材質の環境光寄与を一時的に25%へ落としたPNGも保存する。これはライティング比較用の値で、アプリの既定IBL強度やプロジェクト保存値は変更しない。強い逆光を作るときは環境光と直接光の比率も評価する必要がある。今回の修正だけで任意のHDRI・Bloom・露出に対する白飛びを完全に防ぐとは扱わない。

## 再現と成果物

`MMD_MODOKI_SSS_ALICIA=1 npm.cmd run test:e2e -- owned-sss-alicia-backlight.spec.mjs`相当の環境変数指定で実行する。Aliciaがない環境・opt-inなしではskipする。`MMD_SSS_CAPTURE_LABEL`で保存先、`MMD_SSS_PBR_ONLY=1`でPBRのみの診断を選べる。

比較PNG・観測した厚み分布・照明値・コンパイル済みWGSLはignoredな`local-references/sss-alicia-backlight-2026-09-18/`に置く。`baseline`は透過半減後・陰側補正前、`shadow-fill-limited`は陰側補正後。モデルやtexture、参考画像はコミットしない。

通常の配布fixture確認は`owned-sss-transmission-strength.spec.mjs`で行う。実モデル比較は画質判断の証拠であり、耳・指先の全姿勢や動作中の透過品質の保証にはしない。

検証結果: Aliciaの通常MMD / PBR比較、PBR成分分離、環境光25%の比較が成功。配布fixtureのClassic / FrameGraph E2E 2件（通常MMD / PBR、Skin / Wax、順光 / 逆光、標準 / 最大の32条件）も成功し、ページ例外とWebGPU検証エラーは0件。lint、診断スクリプトの構文検査、insights検証、diff check成功。WGSLの局所変更のため型検査・全単体テスト・単独起動smokeは追加していない。見た目の採否は所有者確認待ち。

## 追補: 陰側の一律な底上げを角度に応じて減らす

所有者の追加実機画像では、改善後も逆光で肌の明暗差が乏しいとの評価があった。所有者が、陰側の一律な底上げを減らして薄部透過・輪郭光を際立たせる処理の試用を指示した。

Skinの陰側の色に`mix(0.5, 1.0, smoothstep(-1, 0, signed N·L))`を追加する。接線方向で従来値、完全に光へ背を向けた面で半分となり、その間は法線方向に応じて連続的に変わる。正のN·Lと、光へ向いた面に落ちる遮蔽影の底上げは従来値を維持する。既存の明部への補間・拡散処理を通して合成する。

通常MMDはworld normalと主方向光からsigned N·Lを求め、PBR Skin / Skin Faceは既存の`NdotLUnclamped`を使う。PBRではgamma側の陰色へ掛けてからlinearへ変換するため、「半分」は陰色の係数を指し、最終画素やlinear光量の50%を意味しない。透過係数0.375・厚み判定・Wax・IBL・直接反射は維持する。

比較画像は`angular-fill/`に保存し、直前の`shadow-fill-limited/`と同じ条件で比較する。Alicia E2Eには追加画像の照明方向(0.2, -1, -0.37)も加える。ただし比較カメラは従来の固定条件を使用し、追加画像の全設定を同一にした再現とはしない。陰側を暗くする試用調整であり、ルックの最終採否は所有者確認待ち。

画像確認: 通常MMDは頬・肩の陰影差が増した。最大斜め逆光の顔下部ROI（1152×648 PNGのx=485..649、y=225..284）でRGB平均の標準偏差は15.15→27.81、平均は170.36→144.12となった。一方、PBRは同ROIの平均245.29→244.37と変化が小さく、既定IBLの加算が強い条件では白さが残る。この調整でPBRの強い逆光を解消したとは扱わない。

今回の検証: Aliciaの4方向・2照明・通常MMD / PBRの比較と、配布fixtureのClassic / FrameGraphを合わせたE2E 3件成功。lint・insights検証・構文検査・diff check成功。型検査・全単体テスト・単独smokeはWGSL内の局所変更のため追加していない。

## 追補: PBR Skin Faceの頬・口元の色むら

所有者の実機評価は「明暗はいいが色むらが気になる」。対象材質はPBR Skin Faceと確認できた。カメラ(0.37, 17.18, -0.45)、回転(2.7, -29.2, 0)、距離10.4、照明方向(0.28, -0.28, -1)、RGB255・照度200、影RGB(128, 94, 128)・Toon100で比較した。影距離などシーン全体の既定値は変更していない。初期HDRIでは白さに隠れるため、診断画像では肌の環境光寄与を一時的に25%にした。ユーザー画像との全設定一致は主張しない。

透過光を止めると頬・口元の島状の明部が消えた。顔の可視57,547画素中46,128画素では光側の入口がなく、入口を得た領域だけが透過する。これは単一入口depthから閉じた頭部の体積を復元できない制約で、欠けた入口を厚み0として扱うバグではなかった。固定ROI内で入口が取れた画素の光方向の厚み中央値は耳0.140、口元0.411、頬0.791（モデル座標系）。頬のような厚い部分にも透過距離0.5では光が残る。

入口描画だけから顔用法線補正を外す、入口をrasterの表裏判定にする、厚み0付近や負値を抑制する、という試作は色むらを解消せず撤去した。視線と法線の角度で顔正面の透過を抑える試作は耳まで弱くなるため撤去した。最終変更は次の2点に限定する。

- PBR Skin Faceの透過減衰距離を0.5から0.15へ短縮する。単なる一律減光ではなく、厚い領域を強く減衰させ、薄い耳の透過を残す。材質IDやモデル名からの推定は行わず、明示的なFaceプリセットのdefineに限定する。
- FaceのSSS連続面判定では、照明用に補正した法線の代わりにworld positionの画面微分から得る幾何法線を使う。normal RTTと最終4tap読出しの両方で揃え、拡散の接平面判定と見た目の法線を分離する。退化した面には元の法線を使う。Babylon.js 9.2.0の`ShadersWGSL/ShadersInclude/pbrBlockNormalFinal.js`にもworld positionの`cross(dpdx, dpdy)`による面法線の計算があり、導入済み実装とGPU実行で確認した。WGSL built-inの一次情報は[W3C仕様](https://www.w3.org/TR/WGSL/#builtin-functions)を参照。

陰側の明暗補正、Faceの照明用法線補正、共通の透過係数0.375、拡散半径0.2、他のSkin / Wax、IBLの既定強度は維持する。口元の実際に薄く計測される部分には弱い透過が残る。任意の開いたモデルの厚みを正しく復元する変更ではなく、モデルの大きさによっても透過距離の相対的な効き方は変わる。

比較画像は`mottle-face-before/`と`mottle-face-geometric-continuity/`、比較表示は`mottle-comparison.html`。同一条件の透過ON/OFF画像差のRGB平均（0–255、物理的な透過率ではない）は、頬12.35→0.35、口元34.67→14.79、耳34.79→23.28。頬の局所的な明部を抑え、口元の角ばった境界が弱まり、耳の透過は残った。額の平均RGBは192.69→192.74で、陰側全体を再び持ち上げる変更にはしていない。見た目の最終判断は所有者の実機確認に委ねる。

再現には既存のopt-inへ`MMD_SSS_REPORTED_MOTTLE=1 MMD_SSS_FACE_PRESET=1 MMD_SSS_PBR_ONLY=1`相当を追加する。Face指定は顔だけで、body / handはPBR Skinのまま。領域別の厚み分布は診断helperへ正規化したROIを明示して採取し、通常の診断へモデル固有座標を混ぜない。

検証: 報告条件のAlicia比較、配布fixtureのClassic / FrameGraph（従来32条件＋Faceの順逆光・標準最大8条件）成功。閉じた厚い頭部と厚さ0.12の耳を持つfixtureのSSS照度bufferでは、透過ON/OFF差の平均が頭0.00562、耳0.69612で、薄部の透過が残ることを両backendで検査した。ページ例外・WebGPU検証エラー0件、lint・診断/E2Eスクリプト構文検査成功。WGSLの局所変更のため全単体テスト・型検査・単独smokeは追加していない。

追加でFaceを指定したAliciaの4方向・標準/最大照明も成功し、順光の通常照明と最大逆光の比較画像を目視確認した（`face-thickness-continuity-angles/`）。最終変更後のE2Eは報告条件1件、配布fixture2件、方向比較1件の計4件。

## 通常モードのSSSを選択肢から外す

2026-09-18、所有者は調整後のPBR SSSを「いい感じ」と評価し、通常モードは暗くなりすぎるため「通常モードでのSSS SkinとSSS WAXをUIから外して」と指示した。通常モードの`SSS Diffusion Skin` / `SSS Diffusion Wax`を非表示プリセットへ追加した。通常の材質セレクターと、その選択肢に合わせるautomation catalogから外れる。PBR Skin / Skin Face / Waxは従来どおり選択できる。

WGSL保存ID、runtime、保存済みprojectの復元と材質一覧のラベル表示は残す。旧projectがこれらを使用していても、セレクターを開くことやPBRモードを切り替えることだけで別材質へ置換しない。互換描画の診断E2Eは、非表示項目をUIへ戻さず、保存projectのfixture供給経路から適用する。

検証は`sss-shader-presets.spec.mjs`と`owned-sss-transmission-strength.spec.mjs`の計3件成功。通常の非表示、旧形式の保存ID維持・一覧表示、標準材質への戻し、PBR Skin / Face / Waxの適用とモード切替、現行mode bank形式の互換描画を確認した。lint・insights検証・構文検査・diff check成功。既存の旧形式テストは新形式の空のmode bankが旧材質配列より優先されるfixture不整合で一度失敗し、旧形式の再現ではbankを除去、現行形式の診断helperではbankも同期して修正した。
