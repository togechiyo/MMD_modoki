# v0.2.x リリースフィードバック台帳

更新日: 2026-09-03

v0.2.0 以降に届いた不具合、要望、UX 上の課題、仕様確認を、v0.2.3 のリリース準備とリリース後確認を含めてまとめて管理する。
初回棚卸しでは、GitHub Issues のうち v0.2.0 リリース日の 2026-07-06 以降に作成されたもの、その期間に完了確認された継続 Issue、X の公開キーワード検索で確認できた投稿を対象にした。

リリースノートに記載済みの既知の制限は、実際の追加報告や想定外の挙動がない限り、この台帳の件数には含めない。

## 運用ルール

- ID は `V022-001` の形式で付ける。
- `対象` には、報告者が確認したリリースを記録する。複数リリースにまたがる場合は範囲で示す。
- 種別は `bug` `request` `spec` `ux` `docs` `investigation` を使う。
- 優先度は `P0` `P1` `P2` `P3` を使う。
  - `P0`: データ消失、起動不能、主要機能が広範囲で使用不能になる。
  - `P1`: MMD の主要編集・保存・出力経路に大きく影響する。
  - `P2`: 回避策がある、条件依存、または実験機能に限定される。
  - `P3`: 軽微な表示、文言、使い勝手、将来改善の候補。
- 状態は `collecting` `investigating` `needs retest` `fix planned` `fixed` `won't fix` `duplicate` を使う。
  - `needs retest` は、関連修正が入った可能性はあるが、元の再現条件で改善を確認できていない状態とする。
- 1 件追加したら「一覧」と「詳細」の両方を更新する。
- GitHub Issue 1 件に複数の症状や要望が含まれる場合は、症状単位で台帳 ID を分ける。
- 過去リリースからの継続案件は、元 Issue または元台帳 ID を詳細に残す。
- 修正作業へ進める項目は、必要に応じて `mmd-basic-task-checklist.md` にタスクを追加し、この台帳から参照する。
- 原因が複数領域にまたがる場合や調査記録が長くなる場合は、個別の調査メモを作り、この台帳は要点とリンクに留める。

## 詳細

### V022-001 Apple Silicon 上で macOS x64 配布物の動作が非常に遅い

- 種類: bug
- 優先度: P1
- 対象: v0.1.x〜v0.2.0
- 発生日: 2026-03-24
- 送信元: [GitHub Issue #5](https://github.com/togechiyo/MMD_modoki/issues/5)
- 状態: fixed
- 環境: M1 Pro / macOS 15.7.4
- 現象: x64 配布物ではモデル読込に1分以上かかり、操作時に10〜20 FPSまで低下する。ARMネイティブのローカルビルドは軽快に動作した。
- 結果: v0.2.0 で Apple Silicon 向け配布物を追加し、Issue は 2026-07-09 に完了としてクローズされた。
- メモ: v0.2.2 では macOS arm64 DMG を継続して配布している。

### V022-002 `mmd-manager.ts` の文字化けコメントでファイルが異常に肥大化

- 種類: bug
- 優先度: P2
- 対象: v0.1.x〜v0.2.0
- 発生日: 2026-03-24
- 送信元: [GitHub Issue #5 のコメント](https://github.com/togechiyo/MMD_modoki/issues/5)
- 状態: fixed
- 現象: コメント行の大量の文字化けにより、約7000行のファイルが12 MB超になっていた。
- 結果: 2026-08-20 時点の `src/mmd-manager.ts` は約646 KBで、報告された異常な肥大化は残っていない。
- メモ: 今後も意味を復元できない文字化けコメントは、挙動へ影響しないことを確認して除去する。

### V022-003 Linux / macOS で PMX テクスチャが白くなる

- 種類: bug
- 優先度: P1
- 対象: v0.2.0
- 発生日: 2026-07-06
- 送信元: [GitHub Issue #13](https://github.com/togechiyo/MMD_modoki/issues/13)
- 状態: fixed
- 環境: CachyOS / AMD RX 6400、および macOS 15.7.7 arm64。Windows 11 では表示できた。
- 現象: v0.1.8 では表示できた PMX のテクスチャが v0.2.0 で白くなった。

### V022-053 動画出力の物理が硬く見え、演算レートを調整したい

- 優先度: P2
- 対象: v0.2.2

- 未確定点: 報告内の「FPS 上昇で物理演算回数が倍になり重力の影響が増す」という説明は nanoem での経験に基づく仮説であり、MMD_modoki の原因としては未確認。

- 2026-09-03 現行main確認: `test/fixtures/accessory/simple-triangle.x`を読込・project round-tripした後、PNG / WebMの双方に明画素が含まれ、両出力の平均pixel差も許容範囲に収まる既存E2Eが成功した。単純なX accessoryの一般的なPNG欠落は再現せず、報告asset、可視設定、透過背景、単発PNG / screenshotの別が不足しているため`collecting`を維持する。

### V022-065 同一pathのモデルテクスチャ変更がアプリ終了まで再読込へ反映されない

- 種類: bug
- 優先度: P2
- 対象: v0.2.3
- 発生日: 2026-09-03
- 送信元: [GitHub Issue #23](https://github.com/togechiyo/MMD_modoki/issues/23)
- 状態: collecting
- 環境: M4 Mac mini / 16 GB / macOS 15.7.9
- 現象: modelを開いたまま外部アプリで同じpathのtexture内容を変更すると、modelの削除・再読込、projectの閉じ直し、新規projectでの再読込を行っても変更前のtextureが表示される。親アプリを終了してから開き直すと変更が反映される。
- 影響範囲: texture loader / engine cache、model dispose、project close / new、複数windowで共有されるprocess state。アプリ再起動で回避できるためP2とする。
- 確認観点: texture URLとcache key、同一pathのmtime / content変更、model dispose後のtexture参照数、同一window / 別window、WebGPU fallback texture cache、通常texture形式とDDS / BMPを分ける。
- メモ: 外部編集したassetのhot reload機能全般を確約する項目ではない。明示的に削除して再読込した場合の期待値と、同一URL cacheの更新規則を先に定める。
- 2026-09-03 再現試行: 同一pathのtextureを赤から青へ上書きし、model削除、blank project読込、同一model再読込、アプリ再起動を比較する最小PMXを一時生成したが、そのPMX自体をexport surface上で有効に描画できず判定不能だった。これは非再現の証拠には数えない。報告assetの利用許可またはtexture付きの配布可能PMX fixtureが必要なため`collecting`を維持する。
