# v0.2.x リリースフィードバック台帳

更新日: 2026-08-24

v0.2.0 から v0.2.2 まで、リリース単位の台帳を作成できていなかった期間に届いた不具合、要望、UX 上の課題、仕様確認をまとめて管理する。
初回棚卸しでは、GitHub Issues のうち v0.2.0 リリース日の 2026-07-06 以降に作成されたもの、その期間に完了確認された継続 Issue、X の公開キーワード検索で確認できた投稿を対象にした。

リリースノートに記載済みの既知の制限は、実際の追加報告や想定外の挙動がない限り、この台帳の件数には含めない。

## 運用ルール

- ID は `V022-001` の形式で付ける。
- `対象` には、報告者が確認したリリースを記録する。複数リリースにまたがる場合は範囲で示す。
- 種別は `bug` `request` `spec` `ux` `docs` `investigation` を使う。
- 優先度は `P0` `P1` `P2` `P3` を使う。
  - `P0`: データ消失、起動不能、主要機能が広範囲で使用不能になる。
  - `P1`: MMD の主要編集・保存・出力経路に大きく影響する。
  - `P2`: 回避策がある、条件依存、または実験機能に限定される。
  - `P3`: 軽微な表示、文言、使い勝手、将来改善の候補。
- 状態は `collecting` `investigating` `needs retest` `fix planned` `fixed` `won't fix` `duplicate` を使う。
  - `needs retest` は、関連修正が入った可能性はあるが、元の再現条件で改善を確認できていない状態とする。
- 1 件追加したら「一覧」と「詳細」の両方を更新する。
- GitHub Issue 1 件に複数の症状や要望が含まれる場合は、症状単位で台帳 ID を分ける。
- 過去リリースからの継続案件は、元 Issue または元台帳 ID を詳細に残す。
- 修正作業へ進める項目は、必要に応じて `mmd-basic-task-checklist.md` にタスクを追加し、この台帳から参照する。
- 原因が複数領域にまたがる場合や調査記録が長くなる場合は、個別の調査メモを作り、この台帳は要点とリンクに留める。

## 詳細

### V022-001 Apple Silicon 上で macOS x64 配布物の動作が非常に遅い

- 種類: bug
- 優先度: P1
- 対象: v0.1.x〜v0.2.0
- 発生日: 2026-03-24
- 送信元: [GitHub Issue #5](https://github.com/togechiyo/MMD_modoki/issues/5)
- 状態: fixed
- 環境: M1 Pro / macOS 15.7.4
- 現象: x64 配布物ではモデル読込に1分以上かかり、操作時に10〜20 FPSまで低下する。ARMネイティブのローカルビルドは軽快に動作した。
- 結果: v0.2.0 で Apple Silicon 向け配布物を追加し、Issue は 2026-07-09 に完了としてクローズされた。
- メモ: v0.2.2 では macOS arm64 DMG を継続して配布している。

### V022-003 Linux / macOS で PMX テクスチャが白くなる

- 種類: bug
- 優先度: P1
- 対象: v0.2.0
- 発生日: 2026-07-06

- 結果: Linux と macOS の両報告者が v0.2.1 で改善を確認し、Issue は完了としてクローズされた。

- v0.2.1 追跡: `@kakurakutekiko1` がモデル全体の白化改善を確認した一方、瞳欠けと半透明材質の問題は残ったため、V022-024 / V022-025 へ分離した。
- 関連: [macOS / Linux file URL テクスチャ白化調査](./mac-linux-file-url-texture-whiteout-2026-07-14.md)

### V022-005 同一モデルを複数読み込むとモーションと位置が混線する

- 種類: bug
- 優先度: P1
- 対象: v0.2.1
- 発生日: 2026-07-18
- 送信元: [GitHub Issue #18](https://github.com/togechiyo/MMD_modoki/issues/18) 1-2-1
- 状態: fixed
- 現象: 1体目へモーションと全ての親の位置を設定した後、2体目へ別モーションを読み込むと1体目と同じ位置へ表示される。
- v0.2.2 関連変更: モデル個体へ安定した instance ID を追加し、モーション、選択、外部親、project 復元を個体単位で扱うよう変更した（`561dbb7`）。
- 確認条件: 同一PMXを2体読み込み、個体ごとに異なるセンターモーションを与えた project round-trip で混線しないこと。
- 関連: [モデル instance ID 実装メモ](./model-instance-id-implementation-2026-08-14.md)
- 2026-08-24 再確認: 自作 `tofu.pmx` fixture を同一パスから2体読み込み、別々の instance ID に X=`0` と X=`12` のセンターモーションを割り当てて project を再読込した。描画ボーン位置の差が `12` のまま維持され、再出力した project でも各 instance ID と埋め込みモーションが読み込み順どおり対応したため fixed とする。確認は Playwright Electron E2E `feedback-core-edit-retest.spec.mjs` で行った。

### V022-027 新規プロジェクトを別ウィンドウで開き、既存プロジェクトを保持したい

- 種類: request
- 優先度: P2
- 対象: v0.2.2
- 発生日: 2026-08-24
- 送信元: プロジェクト所有者から共有された要望
- 状態: collecting
- 要望: `ファイル` メニューなどから新規プロジェクトを作成するとき、現在のウィンドウを初期化・破棄せず、まっさらな編集状態を持つ別ウィンドウを開きたい。
- 期待する結果: 元のウィンドウではモデル、モーション、シーン設定、編集履歴、保存先を維持し、新しいウィンドウでは未保存の空プロジェクトとして独立して編集を開始できる。
- 現行確認: `project.new` Action、`Ctrl+N`、新規プロジェクト用メニュー項目は未実装。Electron main process の `createWindow()` はウィンドウごとに renderer を起動し、PNG 連番 / WebM の background export も `webContents.id` 単位で所有者を管理しているため、既存構成を再利用できる見込みがある。
- 実装候補: `project.new` Action から preload IPC を経由して main process の `createWindow()` を呼び、各 renderer に独立した `MmdManager`、timeline、CommandHistory、project file path を持たせる。言語、UI 表示倍率、既定 renderer / physics backend などのアプリ設定は共有対象として分離する。
- 確認観点: 新規ウィンドウが空状態で開くこと、元ウィンドウの内容と選択・履歴・保存先が変化しないこと、両ウィンドウで保存先が独立すること、一方を閉じても他方が継続すること、background export の進行状態が別ウィンドウへ混線しないことを E2E で確認する。
- 制約: ウィンドウごとに WebGPU engine と物理 runtime を初期化するため、複数の重いプロジェクトを同時に開いた場合は GPU / メモリ消費が増える。初期実装では状態共有やウィンドウ間コピーを必須にしない。
- 優先度判断: アプリ再起動などの回避策はあるが、既存プロジェクトを保持したまま別作業を開始する project workflow の改善であるため P2 とする。
