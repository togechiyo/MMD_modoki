## リリーステーマ

**Timeline / Scene Key Editing**

v0.2.3 では次の流れを一貫させる。

```text
対象を選ぶ
  -> 現在値を確認する
  -> キーを登録する
  -> タイムラインで選択・移動・補正する
  -> 再生 / シークで評価する
  -> project に保存 / 復元する
  -> 1操作単位で undo / redo する
```

表示だけを追加して終わらせず、初期値、キー登録、再生評価、シーク、保存 / 読み込み、undo / redo までを1機能の完了範囲とする。

## 進め方の決定: UI 再配置を先行する

v0.2.3 は、キー機能を先に継ぎ足すのではなく、**アクセサリ欄の移設とシーン編集 UI の置き場所作りから開始する。**

```text
アクセサリの既存操作を棚卸し
  -> 情報欄の対象一覧へ統合
  -> 情報欄 / 下パネル / タイムラインの選択を同期
  -> 旧アクセサリ欄を撤去
  -> 空いた場所へ重力欄の UI 枠を配置
  -> 照明・影・重力のキー機能を順次接続
```

UI 先行段階でも、現在動いているアクセサリ操作を失わないことを移設の完了条件にする。重力など未接続の操作は、押せるのに何も起きない状態にせず、無効表示または準備中表示にする。UI の器を作っただけでは各キー機能の完了扱いにしない。

| 必須 | シーン編集 UI の配置 | 空いた下パネルに重力欄の器を作り、照明・影を含む配置と選択同期を先に固める |
| 必須 | タイムライン現行仕様の更新 | 実装済みの複数選択、copy / paste、undo / redo、VMD 出力を仕様へ反映し、拡張前の正本を整える |
| 必須 | シーン用トラック基盤 | babylon-mmd 外で評価する `modoki-owned tracks` の型、評価、保存、CommandDiff の責務を定める |

| 必須 | フレーム操作整理 | 選択キー操作、時間軸構造操作、値補正を UI / Action 上で分離する |

必須項目が安定しない場合、セルフ影、重力、エフェクトの順に後続版へ送る。エフェクトキーのために照明や基本フレーム操作を遅らせない。

## 1. タイムライン現行仕様の更新

[タイムライン仕様](./timeline-spec.md) には、現在は実装済みの複数キー選択、copy / paste、複数キー移動、undo / redo、VMD 出力が未実装として残っている。新しいトラック種別を追加する前に、現行実装を再調査して仕様を更新する。

更新時は少なくとも次を確認する。

- `KeyframeTrack` とトラックカテゴリの現行型
- モデル / カメラ切り替えと対象選択の関係
- 複数選択、矩形選択、行 / 列 / ALL 選択
- copy / paste / delete / 1フレーム移動
- Action、CommandDiff、HistoryManager の接続
- project 保存 / 復元と VMD 読み書きの境界
- タイムラインのレイヤー分割、可視範囲更新、再描画要求

`src/timeline.ts` のレイヤー分離、更新要求の局所化、可視範囲だけを扱う方針を、新しいシーントラックでも維持する。

## 2. アクセサリ欄の廃止と情報欄への統合

アクセサリはモデルと同じく複数存在する編集対象である。下パネル内に独自の対象セレクタを持たせず、情報欄の Camera / Model と同じ一覧に並べる。

### 目標 UI

```text
情報欄の対象一覧
  Camera
  Models
    Model A
    Model B
  Accessories
    Accessory A
    Accessory B

選択対象
  -> 情報欄の詳細
  -> 下パネルの対象固有機能
  -> タイムライン表示対象
```

対象選択からタイムラインの表示単位を導出し、可能であればモデル / カメラの独立したモード切り替えを減らす。ただし一度に撤去して操作回帰を起こさないよう、対象選択同期を先に実装してから旧切り替えの削除を判断する。

アクセサリ欄を外して空いた下パネル領域は、照明、セルフ影、重力のようなシーン全体で1つの項目に使う。OBJ / PLY などの形式拡張は本計画の必須範囲に含めない。

## 3. シーン用トラック基盤

照明、セルフ影、重力、エフェクトは、PMX / PMD モデルや MMD カメラを主対象とする babylon-mmd のランタイムだけでは完結しない。MMD_modoki が所有して評価する `modoki-owned tracks` として扱う。

各トラックは、少なくとも次の責務を共通化する。

- 安定した track ID と種別
- フレーム番号と payload
- 現在値からのキー生成
- 同一フレームへの上書き規則
- フレーム評価と補間方式
- project JSON への保存 / 復元と旧 project の既定値
- Action -> Command -> 最小差分
- undo / redo 後の runtime、UI、タイムライン同期
- 再生、停止、任意フレームへのシーク

トラックごとの差は adapter / evaluator に局所化し、タイムライン本体へ種別ごとの条件分岐を増やし続けない。

## 4. 照明・影・重力のキー登録

| 対象 | 初期 payload | 補間 | 保存 / 出力方針 |
| --- | --- | --- | --- |
| 照明 | 色 RGB、方向 XYZ | 連続補間 | project 保存を必須。VMD 出力は後続対応可能 |
| セルフ影 | モード、距離 | モードはステップ、距離は連続 | project 保存を必須。VMD 出力は後続対応可能 |
| 重力 | 方向 XYZ、加速度、ノイズ | 値ごとに連続 / ステップを定義 | project 専用。VMD 出力対象外 |

### 照明

最初のシーントラックとして実装する。現行 UI のすべてのライティング設定をキー化せず、MMD の照明モーションへ対応づけやすい色と方向を最小 payload にする。照度を含める場合は、VMD 互換値とは別の MMD_modoki 拡張であることを型と UI で区別する。

### セルフ影

キー対象は MMD 互換寄りのモードと距離に限定する。影品質、bias、cascade、解像度、FrameGraph / PostFX の影表現は project の描画設定であり、セルフ影トラックへ混ぜない。

### 重力

project 独自トラックとして扱う。任意フレームへのシーク時に同じ結果を再現するには、値を更新するだけでよいか、物理状態のリセットと再評価が必要かを先に調査する。シーク結果が履歴依存になる状態では完了扱いにしない。

## 5. タイムライン上のフレーム操作整理

操作を次の3群に分ける。

### 選択キー操作

- copy / paste
- delete
- 前後1フレーム移動
- 選択範囲の一括移動

### 時間軸構造操作

- 空フレーム挿入
- フレーム列削除
- 指定位置以降のキーをまとめて移動
- 選択区間の時間倍率変更

空フレーム挿入とフレーム列削除は、選択中のキーだけを動かす操作ではない。指定位置以降の複数トラックへ影響する `batch key edit` とし、影響範囲のプレビューまたは確認表示を検討する。

### 値補正

- 位置 XYZ の加算 / 減算
- 回転 XYZ の加算 / 減算
- カメラ距離、FoV などの加算 / 倍率
- 対応可能なトラックの数値 payload 補正

再生 / シーク / 現在フレーム移動は編集コマンド群と視覚的に分ける。

## 6. XYZ 補正 MVP

初期版は任意式やスクリプト入力を採用せず、選択キーに対する決定的な数値操作に限定する。

1. 対象キーと対象チャンネルを選ぶ。
2. X / Y / Z の補正量または倍率を入力する。
3. 変更前後をプレビューする。
4. 適用時に1つの CommandDiff を生成する。
5. undo / redo、タイムライン再描画、runtime 更新を同じ経路で行う。

最初はボーン移動とカメラ位置を優先する。カメラ距離と FoV は XYZ と同じダイアログへ置けるが、別チャンネルとして扱う。回転は Euler 角の折り返し、Quaternion 変換、最短経路への影響を調査してから有効化する。

値変換は DOM や Babylon runtime に依存しない pure helper とし、複数キーに同じ補正を適用した結果と逆操作を単体テストする。

## 7. エフェクトキーの実験範囲

v0.2.3 では、FrameGraph / Classic / Experimental の全設定をタイムライン化しない。次の条件を満たすパラメータだけを試験対象にする。

- project 保存値が安定している
- 単一の数値または ON / OFF として評価できる
- backend 切り替え後も意味が変わらない、または backend 固有であることを明示できる
- フレーム評価のたびに shader 再コンパイルや stack 再構築を要求しない
- 二重適用や古い PostProcess の残存を検出できる

候補は露出、Bloom 強度、LUT 強度のような連続値とするが、実コードと backend 差を調査してから1〜2項目に絞る。effect enable / disable のような離散値はステップ評価とし、連続補間しない。

エフェクトキーは通常 UI へ一括公開せず、Experimental または明確に分離された導線で評価する。シーントラック基盤をエフェクト都合で複雑化しない。

## 8. VMD 出力との境界

v0.2.3 のキー編集実装と VMD 出力対応を同じ完了条件にしない。

- 照明とセルフ影は、project 内での編集を先に完成させ、VMD section 出力を後続タスクにする。
- 重力とエフェクトは VMD に対応 section がないため、project 専用データとする。
- モデル / カメラ VMD の既存出力を回帰させない。

- [x] アクセサリを Camera / Model と同じ対象一覧へ統合する
- [ ] 情報欄、下パネル、タイムラインの選択同期を整理する

- [x] 空いた下パネルへ重力欄の UI 枠を配置する
- [x] 未接続の登録操作を無効表示または準備中表示にする

2026-08-20 実装:

- 情報欄の対象一覧へ `.x` / accessory を追加し、選択時は Model に近い専用下パネルへ切り替えるようにした。左から情報、補間、アクセサリ変形を各 1 枠で配置し、右 3 枠は空ける。情報欄には削除、表示、影、名称、種類を置き、XYZ / 回転 / スケールと親モデル / ボーンは独立したアクセサリ変形欄へ収め、モーフ欄は表示しない。
- アクセサリの表示と影の状態は実メッシュへ反映し、project 保存 / 復元対象へ追加する。旧 project に影の値がない場合は、読み込み形式ごとの既存初期値を維持する。
- モデル未読込でもアクセサリが 1 件以上あればビューポートの空シーン案内を隠す。ビューポート右下 XYZ ハンドルの `local / global / accessory` 切替は実際の計算へ接続されていなかったため撤去し、XYZ ドラッグ操作自体は維持する。
- ビューポート上部の「モデル編 / カメラ編」では、選択中の `.x` accessory をモデル編側として扱う。アクセサリだけのシーンでも Camera へ切り替えた後にモデル編へ戻せるよう、モデルがなければ先頭アクセサリを再選択する。内部タイムラインが暫定 Camera である制約とは表示モードを分離する。
- 旧アクセサリ欄と専用セレクタを撤去した。アクセサリ transform キー登録は情報欄の登録ボタンへ統合した。
- 旧アクセサリ欄の位置へ重力欄を追加し、既存 runtime の加速度と方向 XYZ、project 保存 / 復元へ接続した。重力キー登録ボタンは未実装であることが分かる無効表示にした。
- アクセサリ選択中の下パネルは Camera の照明、影、重力欄を混在させず専用レイアウトにする。一方、内部タイムラインは暫定的に Camera 側のままとし、Accessory 独自トラックとの同期は Phase 1 以降に残すため、選択同期全体は未完了のままとする。

## 10. 完了条件

各キー種別は、次の確認が揃った時点で完了とする。

- 現在値からキーを登録 / 上書き / 削除できる
- タイムラインにキー有無と選択状態が表示される
- 通常再生と任意フレームへのシークで同じ値を評価できる
- project 保存 / 読み込みで round-trip する
- 旧 project を既定値で読み込める
- 1操作単位で undo / redo できる
- 対象切り替え後も情報欄、下パネル、runtime が同期する
- backend 切り替えを伴う項目は二重適用と古い経路の残存がない

確認は pure helper / CommandDiff / project round-trip の unit test を優先し、UI の登録導線は focused E2E、起動や runtime 初期化へ触れた場合は smoke を追加する。実描画品質、物理の見え方、MMD 本家互換は手動確認結果も記録する。

## 今回やらないこと

- FrameGraph / Classic / Experimental の全エフェクトパラメータのキー化
- 影品質、shadow bias、cascade、解像度のアニメーション
- 重力 / エフェクトの VMD 出力
- OBJ / PLY / glTF などアクセサリ対応形式の全面拡張
- 任意式、スクリプト、ノードベースによる汎用キー補正
- 新しい汎用 3D シーンエディタへの拡張

## 未決定事項

- 照度を照明キーへ含めるか、MMD 互換の色 / 方向だけから始めるか
- 重力方向、加速度、ノイズの補間規則と、キー通過時の物理再初期化範囲
- フレーム列操作を全トラックへ適用するか、表示中 / 選択中トラックに限定するか
- XYZ 補正の基準をローカル座標、ワールド座標、カメラ座標のどこまで用意するか
- 回転補正 UI を Euler 入力にしつつ、内部 Quaternion とどう整合させるか
- エフェクトキー PoC の最初の対象
