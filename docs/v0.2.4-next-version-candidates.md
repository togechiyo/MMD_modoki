## エフェクトキー再開の検討

2026-09-15の一時休止を経て、2026-10-07に所有者が再び目標として挙げた。再開計画の検討を進める方向を記録し、現在の標準OFFをこの文書更新だけで変更しない。

- 休止時の17種、共通effect track、保存済みデータと現在の公開UIを照合する。以前の指定どおり、没・非表示effectの復活は含めない。
- ガンマ・Bloom等の既存対応から復帰対象を絞る段階案を評価する。最初の対象はまだ指定されていない。
- 数値の補間、ON / OFF・選択値のstep評価、effect単位の登録、既存キーの上書き、Undo / Redo、保存再読込を確認する。
- Classic / Frame Graph、viewport / PNG / WebM、seek・再生・effect stack休止で値と描画が一致するか確認する。構造変更・resource準備・backend差を隠さない。
- グラフエディターとの表示・編集の共通化は別に範囲を決め、キー機能の復帰と全effectのグラフ編集を一度に約束しない。

## 次に範囲を決めるとき

- グラフ表示のみ、またはキー編集まで、どの段階を最初の到達点とするか。
- shortcutの既存Action一覧、設定の保存先・持ち運び、OSごとの既定をどう扱うか。
- 3D形式を最初に何種類扱い、静的配置とanimationの境界をどこに置くか。
- エフェクトキーの復帰対象、既存データの動作確認、登録UI、グラフ表示との境界をどこに置くか。
- PBRの入力マップ、Normal方向、画像の持ち運び、preset切替と材質bankの保存規約をどう揃えるか。外部WGSLへ渡す範囲も分けて決める。
- 保留した機能を再開するか、新機能と今回の不具合調査の順をどう配分するか。

実装着手時は既存のsource key・Action / Command・Undo / Redoを使い、UI初期値、設定・project保存復元、backend切替、GUIの最終状態を確認する。形式追加時もlocal fixtureで検証し、配布アプリのoffline-firstを維持する。
