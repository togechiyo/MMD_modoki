`package.json`、lockfileルート、lockfileのルートpackageの3か所が`0.2.4`で一致。更新前のJSONと比較し、依存関係など版番号以外の変更がないことを確認した。追加したローカル文書リンク31件の参照先と`git diff --check`も成功。今回は文書と版番号のみのため、全単体テスト・GUIテスト・ビルドは再実行していない。

## 多言語の残件

5言語それぞれ1080キー。JSON解析、キーの不足・余剰・空欄なし。キー数の一致は翻訳完了を意味しない。

繁体字中国語・簡体字中国語・韓国語には、物理詳細、WebM出力、一部進捗・通知などに英語の説明文が残る。例は`dialog.physics.title`、`dialog.webmExport.title`、`busy.exportingPngSequence`。PBR / MCP / WGSLなどの技術名や意図して共通にしたプリセット名とは区別する。

公開前に翻訳と実画面確認を行うか、残す範囲について所有者の判断を記録する。設定とタイムラインの局所E2Eのみで全体を合格扱いにしない。

## 公開時の予定配布物

[build-zips.yml](../.github/workflows/build-zips.yml) の`vX.Y.Z`タグpushが4種のビルドとGitHub prerelease公開を起動する。以下は予定名であり、生成済みではない。

- `MMD.modoki-windows-x64-0.2.4.zip`
- `MMD.modoki-mac-0.2.4.zip`
- `MMD.modoki-mac-arm64-0.2.4.dmg`
- `MMD.modoki-linux-x64-0.2.4.zip`

公開前には残件・収録差分・ローカル検証を整理し、公開の了承を得る。タグpush後は各buildとPublishジョブ、実際のassetを確認する。ローカル検証や版番号更新だけでリリース完了とはしない。手順の正本は [リリース手順](./release-process.md)。
