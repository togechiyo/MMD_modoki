# v0.2.5 リリースに向けた棚卸し

更新日: 2026-11-13

## 目標と今回の重点

所有者は **2026-11-14（土）午前（日本時間）までの公開を目標**とし、次版を **v0.2.5**、今回仕上げたい項目を **エフェクトのタイムラインキー登録**と指定した。

具体的には「キー登録ないときはGUIで自由に動かせるようにしたい。これはカメラや照明のキー登録と同じ挙動にする感じ」という指定。キー未登録時のGUI調整とキー登録後の評価の境界を優先して仕上げる。

同日の追加指定で、サポート終了したElectronの更新も今回の対象に加える。更新後のruntimeで最終確認できるよう、週の前半に独立して扱う。

さらに所有者は、色調補正系やBabylon.js標準のレンズフレアなど、軽めのエフェクト追加を**余裕があれば行う低優先度候補**に指定した。キー登録の仕上げ、Electron更新、公開前検証を先行し、追加効果は公開の必須条件にしない。

以下の作業分解・日程・持越し案は、この目標に向けた提案。新機能すべての採用や、tag・Release公開の許可を意味しない。進捗の正本は[基本タスクチェックリスト](./mmd-basic-task-checklist.md#2026-11-10-v025公開に向けた作業)に置く。

## 最優先: エフェクトキー登録の仕上げ

既存の個体方式とRCの経路を使い、次の状態をGUIで確認する。下表は受入条件案。

修正前は、[カメラ・照明のロック判定](../src/editor/scene-playback-control-lock.ts)が「再生中かつ、そのカテゴリのキー数が1件以上」のときだけ入力を止める一方、通常エフェクトのGUI・MmdManagerの値設定・RC3種の編集入口は再生中を一律に拒否していた。所有者は共通側で揃える修正を了承し、11/10に以下の実装・検証を行った。

判定にはtrackの存在ではなくキー数を使う。最後のキー削除後は空trackが残り得るため、再び自由調整できることと履歴・保存も確認する。値調整と、個体の追加/削除/並べ替え・品質変更による資源再構築・出力中の排他は分け、後者の一律解除へ範囲を広げない。

| 境界 | 期待する結果・確認内容 |
| --- | --- |
| キー未登録 | キー0個の効果は停止中・再生中ともGUIで値を調整できる。編集値と見た目を保持し、毎frameのキー評価やUI同期で別の値に戻らない。カメラ・照明の未登録編集と操作感を合わせる |
| 登録値と固定値 | 公開UIのうち登録される値を一覧化する。Luminous RCはenabledのみがキー対象で、強度・範囲・柔らかさは固定値。固定値の追加キー化を今回の仕上げへ混ぜない |
| 登録前のpreview | 「その効果にキーが1つもない」と「キーはあるが現在frameにない」を分けて確認。後者の未登録変更、シーク・再生でpreviewを解除する時点はカメラ・照明の現行仕様を照合し、独自の扱いを増やさない |
| 登録・上書き | 右のエフェクト欄の♢ / ♦、dirty表示、現在frameの登録値が一致する。同じframeへの再登録・Undo/Redoで値が戻る |
| 時間変化 | 数値は定義された補間、ON/OFF・選択値・DoF対象は所定のstep評価。シークと再生で同じ値になる |
| キー・個体の操作 | キーのcopy / paste・移動・削除、最後のキー削除、個体の並べ替え・削除とUndo/Redoで対象を取り違えない。RC3種と通常個体が混在する場面も確認 |
| 保存と出力 | キー0個の静的設定・キー対象外の固定値・登録済みキー・複数個体を保存・再読込して保持。全体OFF/ON・Classic往復後も整合する。previewなしの登録済み状態で、同じframeのviewport・PNG・短いWebMを比較する。未登録previewを出力へ使うかはカメラ・照明の扱いと照合する |

旧17種キーの復帰・移行、没効果の再公開、非表示parameterの追加キー化は含めない。詳細設定は右のエフェクト欄へ集約する[既存方針](../insights/decisions/design-framegraph-layering-and-timeline-together.md)を維持する。

### 2026-11-10 キー0個の再生中編集を実装

- カメラ・照明と共通の判定を使い、`isEffectValueEditLocked(id)`で通常個体とRC3種のGUI・値設定入口を揃えた。同種の別個体も各自のキー有無で判断する。キーがあれば現在frameにキーがなくても再生中はロックする。
- 最後のキーを削除した空trackでは、値変更をbaseへ保存し、一時previewを残さない。次frameでpreviewが消えてUndoの差分照合が失敗する問題も防ぐ。停止中のキーありpreview・補間は従来どおり。
- 数値入力中は毎frameの表示同期でEnter前の入力を上書きしない。エフェクト欄は再生中も開閉できる。固定色、Luminous RCの強度・範囲・柔らかさ、DoF対象も個体のキー有無に従う。
- 個体の追加・削除・並べ替え、キー登録、LUT差替え、samplesやRC範囲・品質の変更は再生中ロックを維持する。RCの強度など値だけの変更では、動くモデルに合わせて自動範囲を取り直さない。

### Electron更新（2026-11-10追加）

以下は11/10の初回調査時点の記録。11/13の採用版・完了範囲は直後の追記を参照。

- `package.json`の指定、lockfile、インストール済みpackageはいずれも **40.4.1**。公式[リリーススケジュール](https://releases.electronjs.org/schedule)では40系のEOLは **2026-07-01**。40系内のpatch更新だけではサポート中へ戻らない。
- 確認時点の[最新安定版一覧](https://releases.electronjs.org/?channel=stable)は45.2.3 / 44.10.2 / 43.8.7。[45.2.3](https://releases.electronjs.org/release/v45.2.3)を第一検証候補にする案で、採用・互換性確認済みではない。実際の更新時にも最新patchを再照合し、選んだ版をmanifestとlockfileへ固定する。古い4月メモの41.3.0候補は現在の更新先にしない。
- 40→45はChromium等も変わるmajor更新。[44の変更](https://releases.electronjs.org/release/v44.0.0)にはmacOS 13以降への最低要件変更、clipboard API変更があり、[45の変更](https://releases.electronjs.org/release/v45.0.0)にはsandboxed preloadの一部Node API削除・ASAR内file descriptorの挙動変更がある。これらと41〜43の変更を使用箇所へ照合し、OS要件の配布案内も揃える。今回の短い調査だけで全変更を非該当と判定しない。
- 更新と確認はElectronを中心に分離する。Forge/Vite/Babylon等をまとめて更新せず、互換性のために必要と判明した依存だけ別途説明して扱う。開発用NodeとElectron内蔵Nodeを混同しない。
- 確認対象はmain/preload/IPC・ローカルfile入出力、WebGPU起動と代表effect、PMX/VMD・物理・保存復元、PNG/WebM、ASAR配布版の起動。`lint` / unit / typecheck・critical、GPU環境の`smoke:launch`と関連E2Eを更新後に実行する。ローカルpackage確認はcross-platformの正式4配布物確認の代替にしない。
- 特にCOOP/COEP・`SharedArrayBuffer`を使うBullet MPR、drop時の`webUtils.getPathForFile`、別windowの出力とWebCodecsを確認する。既存の[`mcp-packaged-export.spec.mjs`](../test/e2e/mcp-packaged-export.spec.mjs)は配布実行ファイル指定がなければskipするため、開発E2E成功だけでASAR/`file://`での出力確認済みにしない。

この追記時点では依存を書き換えておらず、インストール・更新後の動作検証は未実施。ユーザーの更新対象指定と、agentの第一検証候補・確認順序を区別する。
